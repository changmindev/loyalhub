# 보안 점검

2026-09-12 기준. 데모 앱이지만 **공개 저장소 + 공개 배포**라서, 실제로 노출되는 것만 다룹니다.
"점검했더니 문제 없었다"도 결론이므로 같이 적습니다.

---

## 1. 응답 헤더

점검 전 배포본에는 `Strict-Transport-Security` 하나만 있었습니다(Vercel 기본).
`vercel.json` 에 나머지를 추가했습니다.

| 헤더 | 값 | 막는 것 |
|---|---|---|
| `Content-Security-Policy` | 아래 참고 | 주입된 스크립트의 실행·유출 경로 |
| `X-Frame-Options` / `frame-ancestors` | `DENY` / `'none'` | 클릭재킹 — 관리 화면이 남의 페이지에 끼워지는 것 |
| `X-Content-Type-Options` | `nosniff` | MIME 스니핑으로 업로드물이 스크립트로 실행되는 것 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 외부로 나갈 때 경로·쿼리가 새는 것 |
| `Permissions-Policy` | 카메라·마이크·위치 등 전부 `()` | 쓰지 않는 기기 권한을 원천 차단 |
| `Cross-Origin-Opener-Policy` | `same-origin` | 창 참조를 통한 교차 출처 간섭 |

CSP 를 이렇게 잡은 이유:

- `script-src 'self'` — Vite 빌드는 스크립트를 전부 외부 파일로 뽑아내므로
  인라인 스크립트가 없습니다. `'unsafe-inline'` 을 열 이유가 없습니다.
- `style-src 'unsafe-inline'` — **여기는 열어야 합니다.** Radix 가 팝오버·토스트 위치를
  `style` 속성으로 계산해 넣습니다. 막으면 레이아웃이 깨집니다.
  스타일 인라인은 스크립트 인라인과 위험도가 다릅니다.
- `connect-src` 에 `*.supabase.co` — 환경변수를 넣어 실제 DB 에 붙이는 경우를 위해 열어둡니다.
  데모 모드에서는 아무 데도 요청하지 않습니다.

## 2. 개발 서버 노출

`vite.config.ts` 의 `server.host` 가 `"::"` 였습니다 — **모든 네트워크 인터페이스**에 열립니다.
AI 빌더가 자기 미리보기용으로 넣은 기본값입니다.

개발 서버에는 업그레이드 없이는 못 고치는 취약점이 있습니다.

- **esbuild** — 임의의 웹사이트가 개발 서버에 요청을 보내 응답을 읽을 수 있음
- **vite 5** — 최적화 의존성 `.map` 처리의 경로 순회

둘 다 각 메이저의 최신 패치(`vite@5.4.21`)에서도 남아 있습니다.
버전은 못 올려도 **노출면은 줄일 수 있어서** 루프백(`127.0.0.1`)에 묶었습니다.
카페·코워킹에서 `npm run dev` 를 켜두는 것과, 같은 Wi-Fi 에 파일을 열어두는 것은 다릅니다.

다른 기기에서 확인해야 할 때만 `npm run dev -- --host` 로 엽니다.

## 3. 알려진 취약점 — 고치지 않기로 한 것

`npm audit` 6건 (high 1, moderate 5). **셋 다 이미 각 메이저의 최신 패치 버전입니다.**
해소하려면 메이저 업그레이드가 필요합니다.

| 패키지 | 등급 | 판단 |
|---|---|---|
| `vite` 5.4.21 | high | 개발 전용. 위 루프백 바인딩으로 노출면 축소. 6/7 업그레이드는 빌드 파손 위험이 더 큼 |
| `vitest` / `@vitest/mocker` 3.2.7 | moderate | 테스트 전용. 배포물에 들어가지 않음 |
| `react-router-dom` 6.30.6 | moderate | **런타임 의존성이라 따로 확인함** — 아래 |

react-router 권고는 `<Link>`·`useNavigate` 의 백슬래시를 통한 오픈 리다이렉트입니다.
이게 위험하려면 **이동 대상이 사용자 입력**이어야 합니다. 전부 확인한 결과
이 앱의 이동 대상은 리터럴 경로 아니면 자체 데이터의 `c.id` 뿐이고,
URL·쿼리·폼 입력이 `navigate()` 로 들어가는 경로는 없습니다.

수정 버전은 `react-router-dom@7` 로 메이저 업그레이드입니다.
**도달 불가능한 취약점을 위해 라우팅을 갈아엎지 않습니다.** 대신 조건을 적어둡니다 —
이동 대상에 사용자 입력을 넣게 되는 날, 이 결정은 무효입니다.

## 4. 점검했고 문제 없던 것

- **XSS** — `dangerouslySetInnerHTML` · `innerHTML` · `eval` · `new Function` 사용처 0건
- **하드코딩된 시크릿** — 없음. `sms-server.cjs` 도 `process.env` 로만 읽음
- **`.env` 추적** — 안 됨. `.gitignore` 에 있고 `.env.example` 만 올라감
- **`target="_blank"`** — 사용처 0건 (reverse tabnabbing 여지 없음)
- **로그로 개인정보 유출** — `sms.ts` 가 남기는 건 **대상 인원수와 문구**뿐.
  전화번호·이름은 찍지 않음
- **문자 발송 경로** — 데모 모드에서 `fetch`·`XHR` 을 가로채고 발송을 눌러
  **네트워크 요청 0건**을 실측 확인. 실수로 문자가 나갈 경로가 없음

## 5. 남은 것

- **`naverApiKey` 를 클라이언트에 저장하는 구조.** 지금은 '데모 범위 밖' 표시가 붙어 있고
  입력값이 localStorage 에만 머무릅니다. 실제 연동을 붙인다면 **키는 서버에 두어야 하고**,
  이 입력칸은 그대로 쓰면 안 됩니다
- **로그인은 데모 인증**입니다. 아무 이메일·비밀번호로 통과하고 `localStorage` 플래그만 봅니다.
  화면에도 밝혀 두었습니다. 실제 인증이 아니므로 **권한 경계로 신뢰하면 안 됩니다**
- Supabase 를 실제로 붙인다면 **RLS 정책이 전제**입니다. anon 키는 공개되는 값이라,
  RLS 없이는 키를 아는 누구나 테이블 전체를 읽습니다
