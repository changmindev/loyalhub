## D-01 · `.env` 없이 실행하면 흰 화면 — 🔴 Critical · ✅ 수정

**재현** 저장소 클론 → `npm install` → `npm run dev` → 브라우저 접속

**기대** README 안내대로 따라 하면 앱이 뜬다
**실제** 백지 화면. `src/supabaseClient.ts` 가 import 시점에 `throw` 해서 앱이 죽는다.
README "시작하기"에는 환경변수 단계가 **한 줄도 없었다.**

**영향** 저장소를 처음 여는 사람이 보는 첫 화면이 백지다.

**수정** 환경변수가 없으면 `throw` 대신 **데모 모드**로 전환.
`mockData` 시드를 `demoStore` 가 제공하고, 상단에 `데모 데이터` 배너를 띄운다.

**수정** `.env` · `.env.local` · `.env.*.local` 추가, `.env.example` 은 예외로 커밋.

## D-03 · 요청 실패 시 무한 "불러오는 중…" — 🟠 High · ✅ 수정

**재현** 유효하지 않은 Supabase 환경변수를 넣고 `/customers` 진입

**기대** 실패했음을 화면이 알린다
**실제** 6초를 기다려도 `불러오는 중...` 이 그대로. 에러 문구 **0건**.

**원인** 두 가지가 겹쳤다.
1. React Query 기본 재시도 3회 + 지수 백오프 → 실패가 드러나기까지 10초 초과
2. 대시보드 · 쿠폰 발송 · 설정 화면에 `isError` 처리가 **아예 없었다**

**수정** `retry: 1` 로 낮추고(`src/App.tsx`), 세 화면에 `QueryErrorNotice` 추가.
데모 데이터로 덮지 않는다 — 실패를 가짜 값으로 가리면 운영에서 DB가 죽어도 화면이 멀쩡해 보인다.

## D-04 · 라벨과 입력칸이 연결돼 있지 않음 — 🟡 Medium(접근성·테스트 가능성) · ✅ 수정

**재현** 로그인 화면 DOM 확인

**기대** `<label for>` ↔ `<input id>` 연결
**실제**
```
label: [['이메일', for=None], ['비밀번호', for=None]]
input: id='' name='' data-testid=None aria-label=None
```
스크린리더가 어느 입력칸인지 읽지 못한다. 자동화도 `placeholder` 에 의존해야 하는데,
문구가 한 번 바뀌면 테스트가 통째로 깨진다.

**수정** 로그인·회원가입 입력칸에 `id` / `name` / `data-testid` 부여, `<label htmlFor>` 연결.
회원가입은 비밀번호 필드가 2개라 `signup-password` / `signup-password-confirm` 로 분리
(작업 중 잠시 **중복 id** 를 만들었다가 검사에서 잡아 정정).

## D-06 · 쿠폰을 발송해도 이력이 남지 않음 — 🔴 Critical · ✅ 수정

**재현** 데모 모드 → `/coupon` → 템플릿 선택 → `발송하기`

**기대** 발송 처리 후 발송 이력에 기록된다
**실제**
```
POST http://localhost:8080/api/send-sms  →  404
토스트: "SMS 발송 중 오류가 발생했습니다"
발송 이력: 변화 없음
```

**원인** `handleSend` 가 `sendSmsToCustomers` 를 먼저 호출하고, 실패하면 `return` 해서
**`createCouponLog` 까지 도달하지 못한다.** 그런데 문자 발송은 이 프로젝트에서
애초에 불가능하다(D-08) — 즉 데모의 핵심 시나리오가 항상 실패하는 구조였다.

**수정** 데모 모드에서는 `sendSmsToCustomers` 가 네트워크 요청을 만들지 않고
`{delivered: false, reason: "demo"}` 를 돌려준다. 이력은 정상 기록되고,
토스트는 `데모 — 실제 문자 없이 N명 발송 건으로 기록했습니다` 로 사실을 말한다.

## D-07 · 대시보드 지표 라벨이 실제 로직과 다름 — 🟡 Medium · ✅ 수정

**재현** 대시보드 진입 (고정 날짜 더미데이터 상태)

**기대** 라벨과 숫자가 앞뒤가 맞는다
**실제** `7일 이상 안 온 손님 0명` 과 `이탈 위험 고객 8명` 이 **동시에** 표시.

**수정** 라벨을 `7~30일 미방문` 으로 정정하고 계산부에 근거 주석.
→ E2E 회귀 대상: 두 세그먼트의 합이 전체 미방문 인원과 어긋나지 않는지 확인할 것.

## D-08 · 실행 불가능한 SMS 서버를 주요 기능으로 안내 — 🔴 Critical(문서 신뢰성) · ✅ 수정

**재현**
```
$ node sms-server.cjs
Error: Cannot find module 'express'
```

**실제** `express` · `coolsms-node-sdk` · `dotenv` 가 **`package.json` 에 없다.**
그런데 README 는 이걸 **주요 기능 표**와 **기술 스택**에 올리고 실행 명령까지 안내했다.

**영향** 문서를 따라 한 사람이 그 자리에서 에러를 본다.
"문자 발송을 붙였다"는 주장 자체를 방어할 수 없다.

**수정** 기능을 만드는 대신 **경계를 명시**했다.
- `sms-server.cjs` 상단에 "참고 구현 · 실행 불가 · 데모 범위 밖" 주석
- README 의 SMS 서술 정정, 실행 불가 명령 삭제
- 쿠폰 화면에 `데모 버전 — 실제 문자는 발송되지 않습니다` 고지
- 실제 발송에는 건당 비용 + 발신번호 사전등록(통신사 심사)이 필요 → 범위 밖

## D-09 · 더미데이터가 고정 날짜라 세그먼트 대부분이 죽음 — 🟠 High · ✅ 수정

**재현** 대시보드 진입

**기대** 방문 최신도 세그먼트가 각각 유의미한 인원을 가진다
**실제** `오늘 방문 0 · 7~30일 0 · 이번 주 0 · 이탈 위험 8`.
시드 날짜가 `2026-02-15~24` 로 고정이라 **전원이 200일 전**으로 몰렸다.
세그먼트 다섯 중 넷이 항상 0 → 자동화가 검증할 구간이 사실상 하나뿐.

**수정** 시드 날짜를 **실행 시점 기준 상대값**으로 생성(`daysAgo(n)`).
모든 버킷에 최소 1명이 항상 존재한다. 상세는 `docs/E2E.md` §3.

## D-10 · 세그먼트 URL 파라미터가 동작하지 않음 — 🟠 High · ✅ 수정

**재현** `/customers?seg=churn` 으로 직접 진입

**기대** 이탈 위험 고객만 보인다
**실제** 전체 10명이 그대로 나온다. 탭 하이라이트도 `전체` 에 머문다.

**원인** `CustomersSegmentsTabs` 는 URL 파라미터를 **쓰기만** 하고(`setSearchParams`),
`CustomerList` 는 `useState("all")` 로 자체 상태를 들고 있었다.
**아무도 URL 을 읽지 않아** 딥링크가 통째로 죽어 있었다.
자동화 관점에서도 치명적이다 — 필터 상태를 URL로 세팅할 수 없으면
모든 테스트가 탭을 클릭해서 상태를 만들어야 한다.

**발견 경위** 더미데이터 버킷을 검증하려고 `?seg=` 로 진입했더니
네 개 세그먼트가 전부 10명으로 나왔다. 데이터 문제인 줄 알고 팠다가 라우팅 문제였다.

**수정** `segment` 의 출처를 **URL 단일 출처**로 변경(`useSearchParams`).
덧붙여 대시보드의 `고객 리스트 보기` CTA 가 `/customers` 로 가던 것을
`/customers?seg=churn` 으로 바꿨다 — 라벨이 `이탈 위험 고객 N명` 인데
전체 목록을 열어주고 있었다.

## D-11 · 데모 전화번호가 실존 가입자 번호일 수 있음 — 🔴 Critical(개인정보) · ✅ 수정

**실제** 시드 데이터의 번호가 `010-1234-5678` · `010-2345-6789` 처럼
**그럴듯한 연속 패턴**이었다. 이런 번호는 실제로 개통돼 있을 가능성이 높다.

**영향** 두 가지다.
1. 공개 저장소에 **남의 번호가 박제**된다
2. 언젠가 발송 경로가 열리는 날 **그 번호로 실제 문자가 나간다**

**지적 경위** 본인이 "0~9 연속으로 집어넣은 건데 실제로 번호 있으면 어떡하냐"고 짚음.

**수정** 전원을 `010-0000-XXXX` 대역으로 교체.
010 번호의 가운데 4자리(국번) **`0000~0999` 는 할당 자체가 불가능한 대역**이다
— 010끼리는 국번만 눌러도 연결되는 구조라 앞자리가 `0` 이면 `070` 등과 혼선이 생긴다.
(같은 이유로 `1000~1699` · `1800~1899` 도 막혀 있다. `1121` 이 `112` 로 연결될 수 있어서.)
즉 **어떤 가입자에게도 도달할 수 없는 번호**다. 형식은 그대로라 검색·표시 테스트는 영향 없다.

하이픈 없는 엣지 케이스(정다은)는 `01000000006` 으로 형식만 유지했다.

## D-12 · 쿠폰 화면이 화면 밖으로 넘침 — 🔴 Critical(레이아웃) · ✅ 수정

**재현** 390px 폭에서 `/coupon` 진입

**기대** 세로 스크롤만 생긴다
**실제** `scrollWidth 682px / 뷰포트 390px` — **페이지에 가로 스크롤이 생긴다.**
카드가 화면 밖으로 뻗어 오른쪽이 잘려 보인다. 360 · 390 · 768px 전부 재현.

**원인** `grid` 자식은 기본 `min-width: auto` 라 **내용보다 작아지지 못한다.**
템플릿 5개(`min-w-[120px]`)가 632px 를 차지하니 카드가 666px 로 벌어졌고,
`overflow-x-auto` 가 달려 있어도 **컨테이너 자체가 늘어나 버려 발동하지 않았다.**

**수정** 그리드와 카드에 `min-w-0`. 이제 `overflow-x-auto` 가 제 역할을 한다.
360 · 390 · 768 · 1440px × 7개 화면 전수 재측정, **가로 넘침 0건.**

## D-13 · 설정 화면의 그룹핑이 의미와 어긋남 — 🟡 Medium · ✅ 수정

**실제** 순서가 `네이버 예약(데모 범위 밖) → 매장 평균 객단가(동작함) → 카카오 채널(데모 범위 밖)`.
**실제로 동작하는 항목이 동작하지 않는 항목 사이에 끼어 있어** 같이 안 되는 걸로 읽혔다.
구분선도 앞쪽에만 있어 시각적 그룹이 어긋났고,
`설정 저장하기` 버튼이 카카오 입력 바로 밑이라 **카카오 전용 버튼처럼** 보였다.

**부수 발견** 하단에 `B2C SaaS 판매용 기본 구조 / … Supabase settings 테이블에 저장됩니다`
라는 **개발 메모가 사용자 화면에 그대로 노출**돼 있었다.

**수정** 동작하는 항목(객단가)을 맨 위로, 연동 2종을 `외부 서비스 연동` 그룹으로 묶고
그룹 단위로 `데모 범위 밖` 배지를 한 번만 달았다.
버튼 문구를 `설정 전체 저장` 으로 바꿔 범위를 명확히 했고, 개발 메모는 사용자 언어 한 줄로 교체.

## D-16 · 화면을 옮겨도 스크롤 위치가 그대로 — 🟠 High(UX) · ✅ 수정

**재현** 단골 목록을 아래로 내린 뒤 고객을 선택

**기대** 상세 화면이 맨 위에서 시작한다
**실제** 목록에서 404px 내려간 상태로 상세에 들어가면 **상세도 404px 지점에서 시작**해,
고객 이름과 `뒤로가기` 버튼이 화면 밖에 있다. SPA 라 페이지를 다시 불러오지 않아
스크롤이 그대로 남는다.

**설계 판단** 단순히 "모든 이동에서 맨 위로" 보내면 **뒤로가기가 망가진다.**
수정 전에는 뒤로 나올 때 보던 자리가 (우연히) 유지되고 있었는데,
일괄 처리하면 목록 맨 위로 튀어 보던 자리를 잃는다. 그래서 방향을 나눴다.

| 이동 | 동작 |
|---|---|
| 새로 들어감(PUSH·REPLACE) | 맨 위에서 시작 |
| 뒤로·앞으로(POP) | 떠날 때의 위치로 복원 |

**수정** `src/components/ScrollRestoration.tsx` 신설.
`useNavigationType()` 으로 방향을 구분하고, 떠나기 직전 위치를 `sessionStorage` 에 저장한다.

⚠️ 복원 시점에는 **목록이 아직 그려지지 않아** 목표 위치까지 스크롤되지 않는다
(문서 높이가 부족해서). 최대 10프레임 동안 `requestAnimationFrame` 으로 재시도한다.

**검증** 목록 404px → 상세 0px → 뒤로 404px / 250px → 0px → 뒤로 250px /
탭 이동 3종 전부 0px.

## D-17 · 캠페인 효과 진행바가 '효과'가 아니라 '발송 규모' — 🟡 Medium · ❌ 미수정

**실제** `최근 캠페인 효과 (추정)` 카드의 막대가
`ratio = sentCount / maxSent` — **발송 인원의 상대 크기**를 그린다.
그런데 막대 바로 아래 문구는 `(추정) 재방문 0명 · 예상 매출 0원` 이다.

`발송 3명 · 재방문 0명` 인데 막대가 40% 차 있으면 **"효과가 40%쯤 있다"로 읽힌다.**
시각 요소와 인접 수치가 **다른 축**을 말하고 있다.

**미수정 이유** 고치는 방향이 두 갈래이고 제품 판단이 필요하다.
(가) 막대를 재방문 비율로 바꾼다 — 데모에서는 대부분 0이라 막대가 거의 안 보인다
(나) 막대 옆에 `발송 규모` 라벨을 달아 축을 밝힌다 — 1줄이지만 '효과' 카드에 규모 막대가 남는다
